# Branch Summary — `gtk3-client-performance-improvements`

All changes relative to the upstream `gtk3` branch fork point (`4285a62`).

---

## GTK2 → GTK3 API Migration

The foundational work on the branch. The client was written against GTK2 and
could not build cleanly against GTK3. The port replaced every major deprecated
API:

| GTK2 API | GTK3 Replacement | Files |
|---|---|---|
| `GdkColor` / `gdk_color_parse` | `GdkRGBA` / `gdk_rgba_parse` | `main.c`, `stats.c`, `inventory.c`, `spells.c` |
| `GtkTable` / `gtk_table_attach` | `GtkGrid` / `gtk_grid_attach` | source files and all 12 `.ui` layout files |
| `GtkHSeparator` / `GtkVSeparator` | `GtkSeparator` with `orientation` property | `dialogs.ui` |
| `GTK_STOCK_YES` / `GTK_STOCK_NO` | mnemonic label strings | `keys.c` |
| `gdk_cairo_create` | persistent `cairo_surface_t` + `draw` signal | `map.c`, `magicmap.c` |
| `gtk_widget_modify_base/bg` | `GtkCssProvider` per widget | `stats.c`, `inventory.c` |
| `GtkStyle` / `gtk_rc_get_style_by_paths` | `GtkStyleContext` + CSS | `info.c` |
| RC-file theme system | stateful CSS provider lifecycle via `apply_theme_css()` | `config.c` |

Two invalid GTK2/X11 color names (`darkorange2`, `grey50`) that GTK3's CSS
parser silently drops were fixed in `standard.css`. A new `black.css` dark
theme was created.

## Windows Build and Packaging

The branch's primary goal. The upstream GTK3 port ran on Linux but could not
be shipped as a Windows installer. Problems fixed:

- **CMake** — X11 detection and Linux desktop icon install rules made
  UNIX-only so the Windows build does not fail
- **Executable renamed** — `crossfire-client-gtk2` → `crossfire-client-gtk3`
- **Windows application icon** — `crossfire.rc` embeds `client.ico` in the
  `.exe`; `main.c` sets the window icon from bundled PNGs at runtime; About
  dialog uses the Crossfire icon
- **Runtime data path** — `CF_DATADIR` is a relative compile-time path that
  breaks when launched from a shortcut. `CF_DATADIR_RT` introduced in `main.h`
  and populated at startup via `GetModuleFileName`; all data lookups use it
- **CSS theme loading** — theme failed to load entirely on Windows; fixed via
  the new provider lifecycle
- **Theme file chooser** — was opening in the wrong directory and showing
  GTK2-format theme files; fixed to use `gtk_file_chooser_set_current_folder()`
  with the absolute themes path on Windows
- **Layout file chooser** — same pattern; fixed to navigate to the installed
  UI directory
- **Path canonicalization** — `g_canonicalize_filename()` called on all file
  chooser results before storing to `client.ini`, guaranteeing absolute paths
- **Window position save/load** — `GtkHPaned`/`GtkVPaned` register as distinct
  GTypes on MSYS2/UCRT64 and do not match `GTK_TYPE_PANED` exactly; switched to
  `g_type_is_a()` so paned positions are actually saved and restored
- **`_WIN32` vs `WIN32`** — MSYS2/UCRT64 defines `_WIN32`, not `WIN32`; all
  existing guards that used bare `WIN32` were silently skipped. All guards
  corrected across `config.c`, `inventory.c`, `image.c`, `keys.c`, `main.c`,
  `main.h`, `menubar.c`
- **`setsockopt` cast** — Winsock2 requires `(const char*)` for the option
  value; the POSIX `int*` was a type mismatch on Windows
- **XPM loader crash** — `libpixbufloader-xpm.dll` causes a fatal startup crash
  on Windows; inventory tab icons rewritten to use inline RGBA data generated by
  `gdk-pixbuf-csource` instead of XPM calls
- **Sounds deployment** — the `sounds/` directory is installed via cmake and its
  presence verified by the smoke test
- **NSIS installer** — `client.nsi` updated for GTK3: correct executable name,
  `PROGRAMFILES64`, Start Menu folder, registry keys; creates Start Menu and
  Desktop shortcuts with the Crossfire icon

## Performance Optimisations

A series of targeted changes to reduce CPU usage during normal play.

### Map renderer (`map.c`)

- **Dirty-region tracking** — skips the full tile-render phase when no cells
  have changed; only the compose phase runs on stable frames
- **`display_mapscroll` blit** — shifts the tile surface in-place on scroll;
  only the newly exposed strip is re-rendered
- **Darkness overlay** — cached `lm_surface` replaces per-frame allocation;
  direct pixel writes replace `cairo_rectangle`/`cairo_fill` pairs
- **RGB24 surface + `OPERATOR_SOURCE`** — removes alpha premultiplication from
  the software rasteriser on the final blit
- **Manual bilinear darkness upscale** — pre-expands the light map before
  writing to `lm_surface`, replacing `CAIRO_FILTER_GOOD/BEST` upscale overhead
- **Direct pixel OVER blend** — smooth sub-tile inner loop writes directly into
  the pixel buffer instead of invoking the Cairo compositor per sub-tile

### Inventory renderer (`inventory.c`)

- **Differential store update** — walks the `GtkTreeStore` and item list in
  parallel; only changed rows are updated; full rebuild only when item order
  changes
- **`GDK_BUTTON_PRESS_MASK`** replaces `GDK_ALL_EVENTS_MASK` on icon-view cells
- **Shared `GtkCssProvider`** for applied-item highlight — was allocated and
  freed per cell per frame; now initialized once and reused

### Main loop and startup

- **Redraw idle guard** — `g_idle_add(redraw)` only called when no redraw is
  already queued, preventing callback accumulation
- **`my_log_handler`** — removed a 1-second `g_usleep` that would freeze the
  client for every GTK log message
- **`image_update_download_status`** — replaced a spin-loop that drained the
  entire GTK event queue with a single `g_main_context_iteration` call
- **`mapdata_animation`** — scan bounded by a high-water mark instead of the
  full 2000-slot `animations[]` array
- **TCP_NODELAY on Windows** — `CONFIG_FASTTCP` now takes effect on Windows via
  a Winsock2 code path alongside the existing POSIX path

## Capsicum Sandbox (FreeBSD)

Restored from upstream commits. `cap_enter()` is called after the server
connection is established on FreeBSD. The sandbox checkbox in the metaserver
dialog is shown but greyed out on Linux/macOS/Windows. `map_pre_sandbox_init()`
pre-loads the Cairo font face before the sandbox is entered since font file
lookups are denied afterwards.

## First-Run Bug Fixes

Two red error messages that appeared on every first launch were suppressed.
Both were caused by the client treating a missing file — expected on a clean
install — as a genuine error.

- **Faceset not found** (`common/image.c`) — When no graphics style (faceset)
  preference has been saved, the client stores an empty string as a sentinel.
  The faceset-matching code interpreted that empty string as a search target,
  found no match, and printed `"Unable to find match for faceset  on the
  server"` in red. Fix: skip the search entirely when the preference is empty.

- **Message Control settings not loaded** (`gtk-v2/src/info.c`) — At startup
  the client tries to read saved Message Control settings from
  `config_dir/msgs`. On a fresh install the file has never been created;
  the client printed a red error naming the full file path. Fix: check `errno`
  after the open fails — `ENOENT` (file not found) is now a silent return;
  other errors (permissions, I/O) still show the red message.
